- `delete this` should only be used when the object is heap-allocated, no-members access it afterwards and no external access. It should cleanup after itself, before being deleted.
- Member initializer lists should always be preferred over assignment inside the constructor body. Assigning in the body means the member is first default-constructed, then reassigned (two operations instead of one) which is wasteful, especially for non-trivial types like `std::string` or `std::vector`. For `const` members and reference members, initializer lists are mandatory, not just faster, since these can't be assigned to after the object exists.
- The `mutable` keyword lets a specific data member of a class be modified even inside a `const` member function, which would otherwise be disallowed.
- Try using smart pointers or containers that manage their own copies (rule of zero). Otherwise, all objects will point to the exact same value and program will crash due to double free or dangling pointer use. The other work-around is a `copy-constructor`, which can be quite time-consuming to write for every single class and will end up following the rule of 3 - which states that if a class needs to define **any one** of these three special member functions, it almost certainly needs to define **all three**: **Destructor**, **Copy constructor**, and **Copy assignment operator**.
- `std::vector` can be optimized easily if we know the situation it will be used in. For example, we can use `.reserve()`. `push_back` constructs a temporary object and then copies or moves it into the vector's storage.`emplace_back` forwards constructor arguments directly, constructing the object in-place with no temporary and no extra copy/move, which is generally more efficient for non-trivial types.. (see how it is done). And many more such in-built functions exist.
- `std::shared_ptr` should only be used when resource constraint is not an issue because it has a considerable overhead from having to maintain a reference counter and list of pointers. `std::unique_ptr` does not have a considerable overhead and must be used as much as possible.
- **Pimpl** (Pointer to IMPLementation) and **Dimpl** (Direct / Fast IMPLementation) are C++ design patterns used to hide a class's internal data members from its public header file. They act as a compilation firewall, breaking compile-time dependencies and maintaining ABI (Application Binary Interface) stability.
